# Streamnest 支付变更预检

适用范围：后续新增收费功能、改价、换主体、域名、供应商或支付平台。复用仓库 docs/billing-integration.md 的现有实现，不重新建设账务系统。

当前证据：本地 main 1c4f5bbda0c7 已包含 Creem 支付实现；原工作流任务的 9 月 26 日审视报告正式购买已开放。这些不等于本轮重验了商户资格或真实 Pro 成功订单。

每次只保存脱敏状态及安全证据引用，不放密钥、证件、银行资料、用户订单原文。

| 项目 | 填写内容 | 通过条件 |
|---|---|---|
| 变更身份 | 产品、平台、代码 SHA、域名、评估人、日期、复核期限 | 对应本次实际版本 |
| 真实能力 | 用户买到什么、数据来源、处理方、保存与删除方式 | 文案与实际功能一致 |
| 主体资格 | 适用主体和地区、官方规则链接及核验日期、证据引用 | 有适用证据，未失效 |
| 产品准入 | 当前能力清单、授权/模型许可、需澄清项、平台答复适用范围 | 逐项证据，不从结算能力推导 |
| 结算资格 | 币种、收款条件、主体匹配的脱敏确认 | 独立确认 |
| 公开一致性 | pricing、terms、privacy、refund-policy、客服、申请材料 | 价格/权益/退款一致 |
| 技术验收 | 支付模式、隔离数据库、签名、幂等、到账、到期、退款、取消 | 复用现有测试；分别记录本地/沙盒/真实证据 |
| 当前缺口 | Pro 成功订单、续费、其他未覆盖项 | 未验收项不能借别项标通过 |
| 决策 | 禁止提交 / 待补证据 / 可提交；依据、签署、下一步 | 可提交仅表示材料齐备，不表示平台批准 |

字段、证据、期限或版本不匹配时回到“待补证据”。明确不适用或存在未解决阻断时为“禁止提交”。正式提交、购买、退款、补积分和修改商户/生产凭据均单独处理。

本模板不固化具体支付平台政策结论。实际申请或业务变更时重新查询官方政策及适用答复；不以旧报告中的规则摘录代替当日核验。
